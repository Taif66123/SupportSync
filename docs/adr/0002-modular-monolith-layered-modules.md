# Modular monolith with layering inside each module

We organize the backend by business module (`auth`, `users`, `tickets`, later `chat`, `notifications`) rather than by technical layer, and inside every module we keep the Router → Service → Repository layering: routers handle HTTP only, services hold business rules and permissions, repositories are the only code that touches the database. This co-locates each feature's logic for locality while preserving the layer discipline; the rejected alternative (all routers / all services / all repositories in top-level folders) scatters one feature across many directories and was deemed worse for maintainability as modules grow. The cross-module boundary: models and schemas are shared contracts and may be imported across modules; services may be called from other modules; repositories stay private to their owning module. Repositories are explicit and boring per module — no generic BaseRepository machinery.
