# SupportSync — Setup + Milestone 1 Plan (revised to use Matt Pocock skills)

## Step 0 — Install the workflow skills (new)
Run in `C:\Github\SupportSync`:
```
npx skills@latest add mattpocock/skills
```
This writes markdown skills into `.agents/skills/` (workspace-discovered by ZCode). Install at minimum: `grill-with-docs`, `codebase-design`, `code-review`, plus `setup-matt-pocock-skills`. Note: `/grill-with-docs` and `code-review` require a **new session** to be discoverable as slash commands — so after installation we restart the session before grilling.

## Step 1 — Requirements grilling (new)
Run `/grill-with-docs` against the SupportSync feature list (your image) to interrogate and pin down requirements, writing the outcomes into `docs/` (product overview, roles, milestones, API contract decisions). This happens **before** architecture finalization, per the skill's intent.

## Step 2 — Architecture design (existing plan, now guided by codebase-design discipline)
Decisions already made with you:
- **Modular monolith** — feature modules (auth, users, tickets, chat, notifications), each internally layered router → service → repository per your whiteboard
- **Alembic from day one** (wired to SQLModel metadata), PostgreSQL + Redis via docker-compose
- **Plan all 4 milestones, implement M1 only** (JWT auth w/ refresh, user management w/ roles, ticket CRUD w/ role-scoped access, Redis rate limiting)

Layout: as previously proposed (`backend/app/core`, `backend/app/modules/*`, `backend/app/utils`, `tests/`, `migrations/`, `docs/`, root `docker-compose.yml`, `CLAUDE.md`).

## Step 3 — Implement M1
1. Scaffold repo layout, .gitignore, .env.example, README, CLAUDE.md
2. docker-compose (postgres + redis)
3. core: config (pydantic-settings), database, security (JWT + bcrypt), redis, errors
4. Alembic init + initial migration (User, Ticket, TicketEvent)
5. auth module (register/login/refresh, require_role)
6. users module, tickets module (role-scoped, paginated), rate limiter
7. seeds/demo.py
8. pytest suite (auth, users, tickets, permission boundaries)

## Step 4 — Quality review pass (uses code-review skill once installed)
Self-review for layering violations, query efficiency, error consistency, security (token expiry, hashing), test coverage — plus the installed `code-review` skill when available in a new session.

## Non-goals
No frontend code yet; no CI/Jenkinsfile until M4.
